Zero Hassle Pipeline

全链路自动化：从硬件唤醒到无感刷新

Next5h 深度整合 macOS 底层电源管理接口与官方 Codex CLI，让任务派发在深睡与锁屏状态下也能完美完成。

01

硬件 RTC 芯片定时唤醒

调用 macOS IOPMSchedulePowerEvent 内核接口，在任务到点前 60s 硬件叫醒 Mac，并申请电源守护阻止深睡断网。

02

Wi-Fi 网络自愈与模型探针

唤醒后，内置 NetworkMonitor 追踪网络握手，并实时读取官方模型缓存与 5H 额度重置倒计时。

03

本地 Codex CLI 静默派发

直调官方 ChatGPT.app/.../codex CLI，精准派发至指定 Project 或历史 Session，支持选模型与 Thinking 强度，锁屏免密执行。

04

codex:// 免重启即时呈现

同步更新本地 session 会话索引与 SQLite 缓存，通过 codex://threads/<ID> 深度协议让运行中的桌面端无感刷新。

Quick Installation

快速安装部署 Next5h

我们为不同偏好的开发者提供了灵活的安装方式，从一键终端脚本到源码编译，开箱即用。

使用 Swift Package Manager 原生 Release 编译模式，打包生成标准独立的 Next5h.app： 

# 1. 克隆项目仓库
git clone https://github.com/KhalilHsu/next5h.git
cd next5h

# 2. 执行一键构建打包脚本 (编译 Swift 二进制并构建 Next5h.app)
./build_app.sh

# 3. 运行并体验应用
open Next5h.app

💡 提示：如需安装至系统应用程序目录，可直接执行：cp -R Next5h.app /Applications/

复制以下单行命令粘贴到 macOS 终端，将自动克隆最新代码、编译 Release 版本并启动： 

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/KhalilHsu/next5h/main/build_app.sh)"

常见问题解答 (FAQ)

关于安全性、唤醒机制与日常使用的常见疑问。

完全支持。 当当前 5 小时窗口额度耗尽时，你无需守在电脑前死等倒计时。直接在 Next5h 中录入想发送的 User Query 加入预定队列。5H 窗口解封瞬间，后台会自动静默派发。你可以选择创建全新独立会话，也可以精准指定发送到 ChatGPT 中已有的 Project (项目) 或追加到历史 Session (会话 Thread)，无缝延续代码上下文；并可自由指定模型与 Thinking 推理强度。
核心在于抢先触发滑动窗口计时。 官方 5H 额度是从你当天发送“第一条消息”起才开始倒计时 5 小时。如果上午 11 点才发首条消息，一天最多只能消耗 1~2 轮。Next5h 每天清晨 07:00 通过硬件 RTC 唤醒电脑发送激活对话，提前开启第 1 个窗口。这样 07:00 (窗口1) ➔ 12:00 (窗口2) ➔ 17:00 (窗口3)，在白天正常工作时间内可以稳稳用满 3 个完整周期，算力价值彻底翻倍！
完全不需要。 Next5h 直接复用官方 ChatGPT macOS 客户端的本地登录认证态，底层调用 /Applications/ChatGPT.app/Contents/Resources/codex 官方原生二进制，零额外密钥依赖，安全纯粹。
可以。 Next5h 基于 macOS 核心服务中的 IOPMSchedulePowerEvent 硬件内核接口，提前 60 秒叫醒 Mac，随后申请 PreventUserIdleSystemSleep 阻止系统深睡，通过静默 CLI 模式执行，无需输入锁屏密码。
纯合盖且无外接显示器状态下不建议。 Apple Silicon 固件为了防止电脑在密闭背包中过热造成硬件损害，在纯合盖时会彻底关闭 Wi-Fi 芯片并进入强制低功耗。如果是接了外接显示器并插电的合盖状态（Clamshell Mode），则 100% 完美支持。
