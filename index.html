01⚡️ 核心价值 01 · 预定发送

02⏰ 核心价值 02 · 清晨定时激活

Local Delivery Pipeline

从排程到本地会话

四种触发策略连接本地 CLI 与桌面会话；执行仍需要应用运行、认证有效和网络可用。

  1. 01

    电源待命守护

    为已排定任务申请 PreventUserIdleSystemSleep；尝试提前 60 秒唤醒，注册可能因权限失败。

  2. 02

    网络与额度检查

    NetworkMonitor 检查网络；读取模型缓存和账号额度，根据会话活跃状态调整探测频率。

  3. 03

    本地 CLI 后台派发

    查找官方本地 CLI，新会话使用 codex exec，已有会话使用 codex queue，传入所选模型与参数。

  4. 04

    会话同步与派发记录

    同步本地会话索引与缓存，记录结果、耗时和参数，并提供 codex://threads/<ID> 会话入口。

Got Questions?

常见问题解答 (FAQ)

关于安全性、唤醒机制与日常使用的常见疑问。

什么是“预定发送”？它可以发送到指定的 Project 或历史 Session 吗？
支持无项目或本地项目的新会话，以及追加到已有会话。选择「5H 解封后」按重置时间 +1 分钟排定；续任务预置默认关闭，需选目标会话后开启。历史记录可复制、再次发送、以此为模板新建或删除单条记录。
晨间预置会改变额度或保证每天三个窗口吗？
不会。它只是每天本地时间 07:00 发送「嗨」，默认使用 6 Luna / low。实际额度与重置时间由官方决定；页面时间轴是排程示意，不是账号额度承诺。已有任务升级后不会被默认模型覆盖。
需要额外配置 API Key 吗？认证数据如何使用？
使用本地 Codex 登录，无需为这条派发链路另填 API Key。额度探针会读取 ~/.codex/auth.json 并请求官方后端；任务也会通过官方 CLI 发往服务端。请勿分享认证文件。
电脑在休眠锁屏状态下，真的能自己唤醒并执行吗？
锁屏、息屏且系统仍运行时，后台 CLI 可执行。有已排定任务时申请防空闲休眠，同时尝试提前 60 秒注册唤醒。深度休眠恢复取决于注册权限、设备状态和网络；不能保证强制休眠后执行。前台模式需要解锁。
MacBook 笔记本合盖放进背包里能自动唤醒吗？
不能依赖纯合盖状态执行。合盖桌面模式需要外接显示器和电源，并确认系统仍在运行；没有外接显示器的合盖状态可能阻止应用与网络工作。
任务执行完毕后，ChatGPT 桌面客户端需要手动重启才能看到吗？
后台派发会同步本地会话索引与 SQLite 缓存，并提供 codex://threads/<ID> 链接。能否即时呈现仍取决于安装的桌面客户端是否支持该协议及本地数据格式。
